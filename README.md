## 沪日 IPLC 到底是什么

IPLC 指的是跨境专线（International Private Leased Circuit），沪日 IPLC 就是上海到日本之间的点对点私有线路。它和普通公网连接的核心区别在于：数据走的是运营商内网专线，从上海入口到日本出口之间不经过公网，所以不会被高峰期跨境拥塞影响。

具体到 Mkcloud 的产品形态，沪日 IPLC 不是一个“节点订阅”，而是一台真正的云服务器或独立服务器：

- 入口在上海，可选 **上海电信** 或 **UCloud 上海 BGP** 两种网络
- 出口在日本，日本侧为 BGP 线路
- 端内延迟（上海入口到日本出口之间）官方标称为 **25~28ms**
- 每台机器配 **2 个独享 IPv4**（入口 IP + 出口 IP 各一个）

这里有一个容易搞混的点：25~28ms 指的是专线端内的延迟，你本机连上入口 IP 之后感受到的总延迟还要加上你到上海入口这一段。也就是说，你实际体验大概是“你家到上海的延迟 + 30ms 左右”，江浙沪用户体验最好，北方和西部会相应增加。

## 流量计费和独享带宽，怎么选

这两类计费方式没有绝对优劣，看你的业务特征：

**选流量计费的情况**：业务流量可以预估、有明显的波峰波谷。比如做中日双向的数据同步、跨境电商的 ERP 对接、日本 VPS 的中转管理。1TB 档 ¥358/月 起步，配合 200M 峰值带宽，瞬时速度可以做得很高，只是总量有限。要注意这里的流量是**双向计算**的，估算用量时别只算单边。

**选独享带宽的情况**：流量难以预估，或者对带宽稳定性有要求。比如部署对日本方向的持续传输服务、需要保证稳定吞吐的业务。5M 独享 ¥600/月起，带宽独享意味着不会被同线路其他用户挤占，代价是不限流量之下单价其实不低。

一个简单的判断方法：如果你的月流量超过 2TB 且比较持续，独享带宽往往更划算；如果只是每天几十 GB 的常规使用，流量计费便宜得多。

另外，两种网络入口的实际差异在于：上海电信入口的独享带宽档位更便宜（5M 差了 ¥100/月），而 UCloud 上海 BGP 入口理论上对多运营商用户的兼容性更好一些。拿不准的话，5M 独享档两个入口都只差一百块，各开一台测试再决定也不算浪费。

## 购买流程和下单前必须知道的几件事

Mkcloud 是 WHMCS 架构的自营面板，下单流程本身不复杂：选套餐 → 选操作系统（Ubuntu、Debian、CentOS、Rocky、FreeBSD 等都有）→ 填写省份 → 付款 → 控制面板装系统。支付方式目前**只支持支付宝**。

但有几个限制是购买前必须清楚的，建议逐条确认：

> **省级白名单**：所有专线产品只允许一个省份的 IP 连入，下单时必须选择你所在的省份，开通后其他省份的 IP 无法连入。后续可以切换省份，但这是防滥用机制，不是可选项。
>
> **需要中国实名**：产品需遵守中国法律，需要中国身份信息实名，仅限个人或企业正规用途。官方明确表示是为了防止机场、回国等违规用途。
>
> **退款政策**：仅支持质量问题退款，且需要提供具体的延迟、速度数据证明。服务开通后**不支持更换到其他地域**，沪日开通了就是沪日，不能改沪港。
>
> **卖的是服务器**：你拿到的是一台完整的云服务器/独立服务器（含 2 个独享 IPv4），需要自己装系统、部署应用，不是一个开箱即用的“节点服务”。

第三条尤其值得留意。如果你想买沪日、之后又想换成沪港或广港，这条路是走不通的，下单前想清楚出口地域再说。

## 常见问题

**沪日 IPLC 的延迟真有 25ms 那么低吗？**

25~28ms 是上海入口到日本出口的端内延迟，这部分由专线保证，也是这类产品最核心的价值。你实际感受到的延迟取决于你到上海入口的网络质量，总延迟一般在你到上海的延迟基础上再加 30ms 左右。

**一台机器能带多少人使用？**

这取决于你拿它做什么。1 核 2GB 的 1TB 档跑轻量转发或单业务没问题；4 核 8GB 的档位可以承载更重的应用。建议按“业务量 × 2”的原则预留配置，专线产品不支持中途免费换地域，宁可起步稍高。

**能不能先买一个月试试？**

可以。所有套餐都支持月付，试用成本最低就是一档月付价格。先用 1TB 或 5M 独享档测试到你本地环境的实际延迟和丢包，确认质量没问题再考虑长期套餐。

**2 个 IPv4 是什么用法？**

入口 IP 是你国内侧连接用的地址，出口 IP 是你在日本侧呈现的公网 IP。做业务备案对接或需要对日方向固定出口 IP 的场景，这个设计比较省心。
